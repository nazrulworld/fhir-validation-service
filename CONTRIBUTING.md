## Workflow

- Run `./mvnw verify` before opening a pull request (needs Docker for the Testcontainers tests).
- Features follow the spec-driven flow in [`.specify/memory/constitution.md`](.specify/memory/constitution.md):
  specify → clarify → plan → tasks → implement.
- Record user-visible changes in [`CHANGELOG.md`](CHANGELOG.md).
- Third-party license information is generated by the build. When a new dependency brings a new license, the build
  fails until its text is added under `src/main/resources/META-INF/third-party-licenses/` and its entry is explained in
  `src/main/resources/META-INF/THIRD-PARTY-CLARIFICATIONS.md`.

## Documentation site

The user guide is written in the [project wiki](https://github.com/nazrulworld/fhir-validation-service/wiki) and
published automatically to <https://nazrulworld.github.io/fhir-validation-service/> by
[`.github/workflows/docs-site.yml`](.github/workflows/docs-site.yml) (spec
[`011-docs-github-pages`](specs/011-docs-github-pages/spec.md)). Edit the wiki, never the site; generated files are
never committed.

- A wiki page edit in the browser rebuilds and deploys the site within minutes. Wiki changes pushed with git may not
  start a build: run the workflow by hand (**Actions → Documentation site → Run workflow** on `main`, or
  `gh workflow run docs-site.yml --ref main`).
- A push to `main` rebuilds the site when it changes `site/`, the converter, or a repository file the site publishes
  (a file the wiki links to, such as `CHANGELOG.md` or `src/main/resources/openapi.yaml`).
- The build fails, and the published site stays as it was, when a wiki page links to a missing wiki page
  (`[[Page]]`) or to a section anchor that does not exist.
- Repository files linked from the wiki as `https://github.com/nazrulworld/fhir-validation-service/blob/main/<path>`
  are published under `/reference/`: Markdown as pages, the OpenAPI definition as a rendered API reference, other
  text files (`.yaml`, `.json`, `.sh`, `.env*`) as downloads.

### Preview locally

Prerequisites: Python 3.10 or later, Ruby 3.4 with Bundler, and Node 22 (for the API reference page). The macOS system
Ruby is too old; install a current one (for example `brew install ruby`) or run the Ruby steps in the `ruby:3.4`
container.

```sh
git clone --depth 1 https://github.com/nazrulworld/fhir-validation-service.wiki.git target/wiki-src
python3 -I -m unittest discover -s scripts/tests/docs-site       # converter tests
sh scripts/tests/docs-site/test_editor_check.sh                    # wiki-editor check tests
python3 -I scripts/build-docs-site.py --wiki target/wiki-src      # add --no-redoc to skip Node
export BUNDLE_GEMFILE=$PWD/site/Gemfile
bundle install
bundle exec jekyll build -s target/docs-site/src -d target/docs-site/_site \
  --config target/docs-site/src/_config.yml,target/docs-site/src/_config.generated.yml
bundle exec htmlproofer target/docs-site/_site --disable-external --assume-extension .html \
  --swap-urls '^/fhir-validation-service:' --ignore-files '/openapi\.yaml\.html$/'
bundle exec jekyll serve -s target/docs-site/src \
  --config target/docs-site/src/_config.yml,target/docs-site/src/_config.generated.yml
# open http://localhost:4000/fhir-validation-service/
```

The converter output is deterministic, so the same wiki revision and commit give the same site as CI.
`DOCS_SITE_JEKYLL_TESTS=1` and `DOCS_SITE_REDOC_TESTS=1` also run the tests that need Jekyll or Redocly (CI sets both).

### One-time setup (repository admin)

```sh
gh api -X POST repos/nazrulworld/fhir-validation-service/pages -f build_type=workflow
gh repo edit nazrulworld/fhir-validation-service --homepage https://nazrulworld.github.io/fhir-validation-service/
gh api repos/nazrulworld/fhir-validation-service/pages --jq .build_type    # expect: workflow
```

Then, in the browser: **Settings → General → Features → Wikis**, tick **Restrict editing to users in teams with push
access** (there is no API for this setting). Every wiki edit is published; the workflow also refuses to deploy an
edit whose editor has no push access, but the restriction is what keeps such edits out of the wiki.
