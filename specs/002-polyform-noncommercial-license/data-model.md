# Data Model: PolyForm Noncommercial 1.0.0 Licensing

This feature adds no database tables, no Flyway migrations and no API payloads. Its "data" is
a small set of files, which are committed or generated at build time. Exact paths inside each
package are listed in [contracts/distribution-layout.md](./contracts/distribution-layout.md).

## Project license (`LICENSE.md`, repository root)

| Part | Rule |
|------|------|
| Required Notice | Line 1: `Required Notice: Copyright 2025-2026 Md Nazrul Islam (https://github.com/nazrulworld)` |
| Separator | Exactly one blank line |
| License body | Byte-identical to the official PolyForm-Noncommercial-1.0.0.md at tag `1.0.0`; SHA-256 `c0ea4a89…fabbe5` (research R1) |

- **Lifecycle**: Only the copyright year range is ever edited (for example `2025-2027`).
  Changing the body fails `LicenseFileTest`.
- This file is the single source for the jar's `LICENSE.md` and the image's
  `/app/LICENSE.md`. Both are copied from it, never edited separately.

## Third-party listing (`META-INF/THIRD-PARTY.txt`, generated)

There is one line per bundled runtime artifact:
`(<license> [(<license>)…]) <name> (<groupId>:<artifactId>:<version> - <url>)`.

- `<license>` values are normalised to SPDX ids through `licenseMerges`.
- **Validation**:
  - Every artifact in compile or runtime scope appears in the listing.
  - No artifact has `Unknown license`.
  - Every license id is in `includedLicenses`. Otherwise the build fails (FR-015).
- **Lifecycle**: Regenerated on every build. It is never committed.

## Missing-license overrides (`src/license/THIRD-PARTY.properties`, committed)

- Format: `groupId--artifactId--version=<SPDX id>`. The first entry is
  `jakarta-regexp--jakarta-regexp--1.4=Apache-2.0`.
- Each entry MUST have a matching section in the clarifications file explaining the source
  of the claim.

## License texts (`META-INF/third-party-licenses/<SPDX-id>.txt`, committed)

- There is one file per SPDX id in `includedLicenses`. Its name is exactly the SPDX id.
- **Initial set**: `Apache-2.0`, `MIT`, `BSD-2-Clause`, `BSD-3-Clause`, `EPL-2.0`, `MPL-2.0`,
  `Unicode-3.0` and `CC0-1.0`. Add `EPL-1.0` only if an artifact is ever offered under it
  alone.

## Clarifications (`META-INF/THIRD-PARTY-CLARIFICATIONS.md`, committed)

There is one section per clarified artifact or group. Each section gives:
- the coordinates,
- the licenses that are offered,
- the license elected or asserted,
- the reason or source,
- source-availability notes where the license requires them (MPL-2.0, EPL-2.0).

Each override in `THIRD-PARTY.properties` and each election from a multi-licensed artifact
MUST have a section here.

## Merged NOTICE (`META-INF/NOTICE`, generated by shade)

- The preamble is the project's Required Notice line followed by
  "This product includes third-party software; see META-INF/THIRD-PARTY.txt."
- The preamble is followed by the merged NOTICE contents of every bundled dependency.
